# Исправления по пяти аннотациям пользователя

## 1. Решение и объём

- История: не создавать общий `updated` на каждое сохранение. Записывать `status_changed` для фактической смены статуса, `due_changed` для реального изменения срока, `edited` для изменения названия/описания/формата/родителя/проекта/меток (перечень изменённых полей в data). Несколько реально изменённых аспектов могут иметь конкретные события, но общий дубль отсутствует. Сохранение без изменений и перенос на прежнюю дату не создают события. Событие выполнения подзадачи в истории родителя сохраняется.
- Старые записи истории не удалять из БД. При выдаче API пустой legacy updated, следующий непосредственно после события статуса/срока той же задачи в пределах секунды, скрывать как старый дубль; самостоятельный updated показывать как edited («Редактирование»). Проекция оставляет исходный журнал пригодным для проверки.
- Типографика: Inter для всего текста и элементов управления, Manrope для заголовков/бренда; применить к body/dialog и всем формам вне .app. Локальные шрифты уже есть. Код Markdown может оставаться моноширинным. Проверить вычисленные шрифты во всех диалогах и семи экранах.
- Проект: новая/редактируемая форма остаётся диалогом, ширина 980px как форма задачи, с адаптацией к окну и внутренней прокруткой. Многострочное описание с переключателем Текст/Markdown и безопасным живым предпросмотром; метки с Enter/запятой, удалением и автодополнением как у задач. При просмотре проекта отображать отрендеренное описание и метки.
- Цвет: собственный встроенный выбор вместо системного окна: вкладки «Палитра» (10 различимых насыщенных пресетов) и «RGB» (R/G/B 0–255, HEX, предпросмотр). Общая нижняя часть — 20 ячеек последних цветов, ровно 2 ряда по 10; незаполненные ячейки не изображают выдуманную историю. Использованным считается цвет успешно сохранённого проекта. История уникальная, свежий цвет первым, максимум 20, нормализация #RRGGBB, хранение отдельно для пользователя в SQLite. Отмена формы не добавляет цвет. История сохраняется после перезагрузки и доступна на другом устройстве этого пользователя.

## 2. Компоненты и API/схема

app/main.py, app/static/app.js/app.css, tests/test_api.py, описание схемы/README. Миграция добавляет projects.description_format TEXT NOT NULL DEFAULT 'text', projects.labels TEXT NOT NULL DEFAULT '[]'. Новая таблица project_colors(owner_id INTEGER FK users.id, color TEXT, used_at TEXT UTC), составной PK(owner_id,color). Добавлять столбцы через PRAGMA+ALTER в идемпотентной транзакции, без пересоздания существующих данных. SQL INSERT с явным списком столбцов.

ProjectIn расширить description_format/labels с теми же ограничениями, что у задачи; старые клиенты без полей сохраняют совместимость. GET /api/projects возвращает эти поля и computed description_html из того же безопасного renderer, что Markdown задач. POST/PUT проекта обновляет последние цвета в той же транзакции. GET /api/project-colors возвращает массив максимум 20 HEX-строк текущего пользователя. Старые цвета проектов могут заполнить пустую историю при миграции. Изоляция и CSRF обязательны.

## 3. Ограничения

Существующие пользовательские данные сохраняются. До рабочего обновления ведущий агент делает SQLite backup. Один исполнитель записи; не занимать рабочий стол и не открывать системный picker, все тесты headless. Не устанавливать пакеты в пользовательский Python — только существующие .venv/.qa-venv. Новых зависимостей не требуется. Docker и Git выполняет ведущий агент. Временные тестовые ресурсы обязательно удаляются в finally, с сохранением логов и проверкой отсутствия; рабочий todo-todo-1 и todo_todo_data не удалять.

Пользователь новым явным указанием снял запрет GitHub, дал репозиторий grunsh/ToDo-list и запросил ветку, коммиты, PR и его объединение. Токен git.txt не читать/печатать исполнителю; GitHub и секреты обрабатывает ведущий агент.

## 4. Приёмка

API: точные события для статуса/срока/редактирования/no-op; старые дубли скрыты и standalone редактирование сохранено; миграция старой схемы идемпотентна и сохраняет данные; проекты Markdown/метки roundtrip и XSS; недопустимый формат/цвет/метки отвергаются; recent colors 20 MRU, dedupe, RGB persistence, межпользовательская изоляция. Словарь покрывает все столбцы.

Headless: computed fonts диалогов, полей и кнопок; новая и редактируемая форма проекта/Markdown/метки; picker tabs/presets/RGB/recent rows/отмена/сохранение/перезагрузка; desktop1714x1243 и mobile390; существующие 21 сценарий без регрессий. Ведущий агент проверяет миграцию на копии рабочей БД, создаёт backup, обновляет контейнер, проверяет сохранность, фиксирует коммиты и объединяет PR.
