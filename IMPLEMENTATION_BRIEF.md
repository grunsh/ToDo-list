# Техническое решение и передача реализации

Источник: полный доступный текст чата «Уточнение требований приложения» (6af60fd8-9f50-83eb-bfb2-30195509c2c1), прочитан 12.11.2026; семь макетов и todo-design/README.md. Изображения вложений чата API не возвращает; локальные макеты доступны. Текущие глобальные инструкции запрещают публикацию GitHub и имеют приоритет над старым запросом публикации.

## 1. Утверждённое техническое решение и объём

FastAPI + SQLite + статический HTML/CSS/JavaScript, один процесс сервера и один Docker-контейнер. SQLite на постоянном именованном томе. Порт по умолчанию 127.0.0.1:18080; на момент проверки свободен. Часовой пояс приложения Europe/Moscow. Все семь экранов, функции и стиль из todo-design/README.md входят в объём; добавляются вход и подтверждающие диалоги в том же стиле.

Три статуса waiting/in_progress/done. На главной «План на сегодня» показывает задачи сегодня (включая исполненные для прогресса), затем открытые без срока. Просроченные — только открытые. Проекты создаются и редактируются, не удаляются. Родитель и потомки относятся к одному пользователю и проекту (либо все вне проекта); циклы запрещены; завершение родителя не завершает потомков. Смена проекта задачи с потомками требует сохранения этого инварианта; в первой версии отклоняется с понятной ошибкой, если связи станут несовместимы. Удаление задачи каскадно удаляет всё дерево только после предварительного показа полного списка и явного подтверждения. Сервер повторно сверяет состав дерева при подтверждении, чтобы не удалить новые невиденные пользователем подзадачи. Дублирование копирует только выбранную задачу без потомков, со статусом waiting и новой историей.

Массовый перенос меняет только явно выбранные задачи, атомарно, после диалога с датой и полным перечнем. Кнопки чёрные в покое, белые только :active. Срок хранится как календарная ISO-дата. Главная помещается в экран, скроллятся четыре виджета; мобильная адаптация соответствует макетам.

Пользователи создаются CLI, публичной регистрации нет. Три тестовых пользователя создаются явно bootstrap-командой с паролями из локального файла вне Git/Docker image. Пароли хешируются scrypt с уникальной солью. Случайные сессионные токены, в БД только хеш, HttpOnly/SameSite cookie; CSRF для мутаций, проверка Origin. После трёх неверных входов простая одноразовая арифметическая капча и ограничение частоты попыток. Изоляция по owner_id во всех чтениях/записях, истории, связях и пакетных операциях. Markdown без исполнения HTML/JS. Не использовать секреты из git.txt.

## 2. Компоненты

app/ — сервер, схема/словарь БД, CLI и статический интерфейс; tests/ — API и браузерные проверки; Dockerfile, compose.yaml, requirements.txt, .dockerignore, .gitignore; README.md и docs/ — запуск, команды, ER-модель и описание каждого столбца. todo-design/ и UI/ сохраняются как исходники дизайна.

## 3. Ограничения

Один исполнитель записи, ведущий агент принимает архитектурные решения и проводит итоговую проверку. Не обращаться к GitHub на запись, не читать/выводить git.txt. Не управлять рабочим столом, мышью, окнами, клавиатурой или буфером обмена. Допустимы CLI/API и headless-браузер. Никаких внешних аналитик, публичной регистрации и совместной работы. Секреты, runtime БД и отчёты исключаются из образа/репозитория.

Docker: до/после проверки учитывать только ресурсы этой задачи; уникальные имена/метки и отдельный compose project; сохранять логи вне контейнера; finally удаляет временные контейнеры, сети и исключительно тестовые тома, затем проверяет отсутствие. Не удалять неизвестные/постоянные ресурсы. Рабочее развёртывание, оставленное пользователю для использования, маркировать purpose=persistent; это не тестовая среда.

## 4. Критерии готовности и проверка

API: вход/выход/CSRF/капча/ограничение попыток; изоляция двух пользователей включая IDOR и атомарность массовых операций; создание/правка проектов и задач, циклы/границы проекта, неизменность статусов потомков, удаление с точным подтверждением, история/метки/дубликаты. Словарь описывает каждый реальный столбец SQLite. БД переживает пересоздание контейнера с тем же томом. Контейнер non-root, healthcheck.

Браузер headless: семь маршрутов, вход/выход, быстрый ввод, поиск/фильтры/дерево, создание/правка проекта и задачи, Markdown preview и безопасность, подтверждение переноса и удаления, скриншоты 1440x900, 1920x1080 и мобильного вида; главная без прокрутки страницы на desktop. Проверить ошибки браузера. Сверить со скриншотами исходных макетов. Запуск Compose и HTTP health, три тестовых логина в итоговом сообщении. Документация с русскими пояснениями схемы и существенной логики, без фиктивных обещаний готовности.

## 5. Запрос решения

Если требуется изменить архитектуру, зависимости, публичный API, схему, безопасность или объём, исполнитель возвращает ведущему агенту конкретный вопрос и варианты, не принимает решение самостоятельно. Разрешённые зависимости: FastAPI, Uvicorn, Pydantic, Python-Markdown, bleach; pytest/httpx для тестов, Playwright для headless QA. Версии фиксировать после проверки доступных пакетов. Визуал — существующие CSS и inline SVG, без нового UI-фреймворка.
